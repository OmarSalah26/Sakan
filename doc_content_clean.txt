 SAKAN Student Housing Marketplace — Egypt Functional Requirements Document (FRD) ⚠️ Language Notice This document is written in English for technical documentation purposes only. The entire application UI, all user-facing text, all labels, buttons, forms, error messages, notifications, and tooltips must be implemented in Arabic. Any AI agent or developer reading this document must treat Arabic as the sole language of the product interface. Platform language Arabic (UI). English (documentation only). Revenue model Paid listings. No transaction commission. Students use the platform for free. Contact off-platform All communication between students and advertisers happens outside the platform via phone or WhatsApp. 1. Platform Overview Sakan is Egypt's first marketplace dedicated exclusively to student housing. It connects displaced students searching for accommodation with property owners and brokers who have units available to let. The platform's role is discovery and qualification only. It does not process payments between students and landlords, does not manage lease agreements, and does not intermediate the financial relationship between parties. All contact and negotiation happens off-platform via phone or WhatsApp. The platform operates across all Egyptian governorates from day one. Revenue comes entirely from advertisers (owners and brokers) who pay listing fees. Students use the platform at no cost. 1.1 User Types Type Who they are Account required to browse? Student Displaced student searching for housing in another governorate. No. Account only required to submit a rating or complaint. Owner Direct property owner renting to students without a broker. Account created when they tap &quot;أضف إعلانك&quot;. Broker Intermediary managing multiple units across a neighborhood or district. Account created when they tap &quot;أضف إعلانك&quot;. 1.2 What Is Out of Scope for MVP Listing analytics and performance dashboards for advertisers. Automated smart alerts based on view-to-contact ratio analysis. Document upload and manual verification badge (&quot;موثق&quot;). In-app messaging between students and advertisers. Payment processing between students and landlords. 2. Account System 2.1 Authentication Rules Phone number is mandatory for all account types. OTP verification via SMS is the primary authentication method. Password-based authentication will also be supported. Unverified accounts do not exist in the database. An account record is only written after OTP is successfully confirmed. If a phone number already exists in the system when a user tries to register, they are redirected to the login flow. Login for returning users is phone number + OTP, or phone number + password once password-based authentication is set up. 2.2 Account Type Rules Account type (student, owner, broker) is selected during registration and is permanent. It cannot be changed after creation. Account type is visible to students on every listing the advertiser posts. The distinction between owner and broker is mandatory and structural. It determines whether a commission field appears in the listing form and how the listing is labeled in browse. 2.3 Onboarding — Advertiser (Owner or Broker) Triggered when any unauthenticated user taps &quot;أضف إعلانك&quot;. Step 1: Account type selection. Two options: مالك or سمسار. Step 2: Phone number entry and OTP verification. Account is written to the database only after successful OTP confirmation. Step 3: Full name (mandatory). Profile photo (optional). Governorates of operation, multi-select (mandatory for brokers — brokers can only list in the governorates declared here). Step 4: Advertiser is redirected immediately to the Create Listing flow. 2.4 Onboarding — Student Triggered when an unauthenticated user taps &quot;rate&quot; or &quot;submit complaint&quot; on any listing. A bottom sheet appears explaining that this action requires an account. Two buttons: &quot;إنشاء حساب&quot; and &quot;تسجيل الدخول&quot;. Account type is pre-selected as طالب and locked (cannot be changed). Steps: phone number, OTP, full name. After completion the student is returned to the action they were trying to complete. 3. Browsing and Discovery Browsing and viewing listings is fully open to everyone without an account. No action is required to browse, filter, or view a listing detail screen. 3.1 Browse Screen The default browse screen displays a feed of all active listings, most recently published first. A filter panel is accessible from the browse screen. 3.2 Filters Filter Input type Matching logic Governorate Single select dropdown Exact match City / Neighborhood Text or dropdown (dependent on governorate) Exact match Price per person Range (min / max) Listing price must fall within range Co-resident gender Single select: male / female Exact match Room type Multi-select: single / double / triple / triple+ &quot;Any of&quot; matching. A listing with a double and triple room appears if the student filters for double. Amenities Multi-select checklist &quot;All of&quot; matching. Listing must have all selected amenities. Advertiser type Single select: owner / broker / any Exact match 3.3 Listing Card Each card in the browse feed shows the following information. No need to open the listing detail to see this. Cover photo (first uploaded photo). Governorate and neighborhood. Room type(s). If the unit has a single configuration (e.g. all double rooms), show the single type label. If the unit has mixed room configurations, show each type present (e.g. &quot;Single + Double&quot;). No generic &quot;mixed&quot; label is used. Price per person only — there is no whole-unit or whole-room price shown. If single room configuration: one price per person. If mixed room configuration: one price per person for each room type, each labeled with that type. Commission amount if the listing is from a broker. Omitted entirely if the listing is from an owner. Advertiser type label: مالك or سمسار. Gender indicator: colored circle, blue for male, pink for female. Total available beds (single updatable number, not split by room type). Premium badge if the listing is on a premium tier. 4. Listing Detail Screen Visible to all users without an account. Contains all information needed for the student to make a decision before making contact. 4.1 Unit Information Section All photos, scrollable gallery (minimum 5, maximum 30). All videos (minimum 1, maximum 3). Full address. Google Maps link if the advertiser provided one. Governorate, city, neighborhood. Room type(s) with price per person for each type. Available beds count. Co-resident gender. Full amenities list, displayed by category (indoor and outdoor). Free-text description written by the advertiser. 4.2 Advertiser Information Section Profile photo (if uploaded). Full name. Account type label: مالك or سمسار. Premium badge if applicable. Overall rating score (average of all submitted advertiser ratings). Commission amount and applicable room type(s) if broker. WhatsApp contact button (opens WhatsApp with the advertiser's number pre-filled). Phone call button. 4.3 Ratings Section Advertiser ratings and property ratings displayed in two separate subsections. Each rating card shows: star count, written review text, photos if any (property ratings only), and the date submitted. Visible to all users without an account. &quot;قيّم المعلن&quot; button and &quot;قيّم السكن&quot; button both visible on this screen. Tapping either triggers the student mid-session onboarding if no account exists. 4.4 Complaint Banner An informational banner visible on every listing detail screen, not blocking, text only: &quot;إذا خالف المعلن أي من التفاصيل المعلنة في السعر أو العمولة، قدّم شكوى من خلال المنصة وسيتم اتخاذ الإجراءات اللازمة.&quot; This banner contains a link that opens the complaint submission flow. 5. Create Listing Flow Accessible to authenticated owners and brokers only. Triggered on first login (redirected automatically after onboarding) and from the advertiser dashboard thereafter. 5.1 Terms Agreement Screen Shown once per advertiser before their first listing is submitted. The &quot;نشر الإعلان&quot; button remains inactive until the checkbox is checked. Acceptance is recorded in the database with a timestamp. Terms shown to every advertiser (displayed in Arabic in the app): 1. All photos and details must be real, recent, and accurately represent the current condition of the unit. 2. The declared price and commission (where applicable) must not be altered at the point of contracting with the student. 3. First confirmed violation: formal warning. Second confirmed violation: permanent ban from the platform. 5.2 Step 1 — Basic Info Governorate (dropdown, for brokers limited to governorates declared during onboarding). City. Neighborhood. Full address (text field). Google Maps link (optional). Inline guidance text shown below the field explaining how to get a Google Maps share link. Co-resident gender: male / female (mandatory). Available beds count (number field, mandatory, updatable after listing goes live). 5.3 Step 2 — Room Configuration The advertiser adds one or more room type entries. Each entry contains a room type selector (single / double / triple / triple+) and a price per person field for that room type. Each additional room type added generates a new price per person field for that type. 5.4 Step 3 — Amenities A predefined checklist organized by category. Listing Management 6.1 Available Beds — Live Updates The available beds count is a single updatable field separate from the full listing edit. The advertiser can update it at any time from their dashboard. This field does not require re-submitting the full listing. 6.2 Auto-deactivation at Zero Beds When available beds reaches zero, the listing is automatically deactivated and removed from browse. The advertiser can manually reactivate it when a bed becomes available again by updating the beds count and tapping &quot;إعادة تفعيل&quot;. 6.3 Saved Listings and Re-publishing All listings are saved permanently to the advertiser's account regardless of status (active, inactive, expired, or manually deactivated). A deactivated or expired listing can be re-published via an &quot;إعادة نشر&quot; button on the advertiser dashboard. The advertiser can update specific fields (available beds, price, photos) before re-publishing without rebuilding from scratch. 6.4 Rating Persistence Ratings are attached to the listing ID, not the subscription period. When a listing is re-published, all previous ratings from past tenants remain visible. Listing status (active/inactive/expired) must be stored as a separate field and must never result in deletion of the listing record or its associated ratings from the database. 6.5 Rating Prompt to Advertisers After marking an interaction as complete (a button on the advertiser dashboard: &quot;هل طلبت من الطالب تقييمك؟&quot;), the advertiser is shown a reminder nudge: &quot;تذكّر أن تطلب من الطالب تقييمك على منصة سكن.&quot; This is an in-app nudge only, no push notification to the student since students are not required to be signed in. 7. Rating Flow Both rating types are accessible from the listing detail screen. No proof of interaction or residency is required. All ratings are auto-published immediately on submission. Students must have an account to rate; if they do not, the mid-session onboarding flow is triggered. 7.1 Rating the Advertiser Step 1: 1 to 5 star rating. Step 2: Mandatory written review. Minimum 20 characters. Placeholder text: &quot;اكتب تجربتك مع المعلن. اذكر السبب بوضوح.&quot; Step 3: Auto-published immediately on submission. 7.2 Rating the Property Step 1: 1 to 5 star rating. Preset options appear immediately after star selection, updating based on the score. Star range Preset options shown 5 stars نظيف جداً / الأسعار مناسبة / الجيران محترمون / موقع ممتاز / المرافق كما هو معلن 3 to 4 stars نظافة مقبولة / الموقع كويس / بعض المرافق ناقصة / السعر مناسب نسبياً 1 to 2 stars غير نظيف / المرافق مش زي ما اتعلن / الموقع بعيد / السعر مش مناسب / مشاكل في الصيانة Step 2: Written review optional. Preset selections from Step 1 are carried forward as the starting text of the field. The student can expand on them or leave them as is. Step 3: Photo upload, optional, up to 5 photos. Step 4: Auto-published immediately on submission. 8. Complaint Flow Triggered from the complaint banner on the listing detail screen. Requires a student account. If no account exists, the mid-session onboarding flow is triggered first. 8.1 Complaint Form Violation type: dropdown with options: السعر المطلوب أعلى من المعلن العمولة أعلى من المعلن تفاصيل السكن لا تطابق الواقع أخرى Description: mandatory text field, minimum 20 characters. Evidence: optional screenshot upload, up to 3 images. 8.2 Submission Confirmation After submission the student sees: &quot;تم استلام شكواك وسيتم مراجعتها واتخاذ الإجراءات اللازمة.&quot; 8.3 Enforcement Rules First confirmed complaint actioned by admin: formal warning sent to the advertiser. Offense counter incremented to 1 on their account. Second confirmed complaint actioned by admin: permanent ban. All their active listings are deactivated. Their phone number is blocked from creating any new account. The ban is enforced at the phone number level, not the account level, to prevent re-registration. 9. Admin Panel Internal tool for platform operators. Not visible to students or advertisers. Must be functional before launch. Polish is not required. 9.1 Complaints Queue List of all submitted complaints, sorted by date (newest first). Each entry shows: student who filed it, advertiser it is against, listing in question, violation type, description text, uploaded screenshots. Two action buttons per complaint: &quot;تحذير&quot; (warning, first offense) and &quot;حظر&quot; (permanent ban). Admin can also dismiss a complaint without action if it is invalid. 9.2 Advertisers Management View all advertiser accounts with: name, phone, account type, offense count, ban status, number of active listings, registration date. Ability to manually ban or unban any advertiser. 9.3 Listings Management View all listings with: advertiser name, governorate, tier, status (active/inactive/banned), available beds, created date. Ability to manually deactivate or remove any listing outside the complaint process. 10. Core Data Model Developer note: Listing status (active / inactive / expired / banned) must be a separate field on the listing record. Deactivating, expiring, or banning a listing must never delete the listing record or any associated ratings from the database. Ratings are permanently attached to the listing ID and must persist across all re-publications of the same listing. 10.1 Users Table Field Type Notes id UUID Primary key phone String Unique. OTP verified. Used as login credential. name String Full name, mandatory. account_type Enum student / owner / broker. Permanent, cannot be changed after registration. profile_photo_url String Nullable. Optional for all account types. governorates Array Brokers only. Governorates declared at onboarding. Limits where broker can list. offense_count Integer Default 0. Incremented on each admin-confirmed complaint. is_banned Boolean Default false. True on second confirmed complaint. Phone number also added to blocklist. terms_accepted_at Timestamp Advertisers only. Null until terms are accepted. created_at Timestamp Account creation timestamp. 10.2 Listings Table Field Type Notes id UUID Primary key. Permanent. Never deleted. advertiser_id UUID Foreign key to users table. governorate String Mandatory. city String Mandatory. neighborhood String Mandatory. address String Full address. Mandatory. maps_link String Nullable. Google Maps share link. gender Enum male / female. Mandatory. available_beds Integer Updatable independently at any time. When set to 0, listing auto-deactivates. room_configurations JSON Array Array of objects: { room_type: enum (single/double/triple/triple+), price_per_person: integer, commission: integer (nullable, brokers only) }. One entry per room type. amenities JSON Object storing all predefined amenity selections plus any custom entries added by the advertiser. photo_urls Array Minimum 5, maximum 30 URLs. video_urls Array Minimum 1, maximum 3 URLs. description Text Free text written by advertiser. tier Enum regular / premium. status Enum active / inactive / expired / banned. Never triggers deletion of the record. subscription_expires_at Timestamp When the paid listing period ends. created_at Timestamp Original creation date. Permanent. Never deleted even if listing is deactivated. target_type Enum advertiser / property. stars Integer 1 to 5. Mandatory. review_text Text Mandatory for advertiser ratings (min 20 chars). Optional for property ratings. photo_urls Array Property ratings only. Nullable. Up to 5 photos. created_at Timestamp Auto-set on submission. 10.4 Complaints Table Field Type Notes id UUID Primary key. student_id UUID Foreign key to users table. advertiser_id UUID Foreign key to users table. listing_id UUID Foreign key to listings table. violation_type Enum price_higher / commission_higher / details_mismatch / other. description Text Mandatory. Minimum 20 characters. evidence_urls Array Nullable. Up to 3 screenshot uploads. status Enum pending / warned / banned / dismissed. actioned_at Timestamp Nullable. Set when admin takes action. created_at Timestamp Auto-set on submission. 10.5 Phone Blocklist Table Field Type Notes phone String Unique. Checked at OTP verification step. Blocked numbers cannot register a new account. banned_at Timestamp Auto-set when ban is applied. 11. Business Rules Summary Rule Enforcement point Commission model (fixed at 0.5 × monthly price per person, or left free for the broker) is not yet decided. To be finalized once the commission model is decided. Brokers can only list in governorates declared during onboarding. Governorate dropdown in create listing step 1 is filtered to declared governorates only. Account type is permanent. No edit option exposed in UI. Type field is immutable in the database. Listing record and its ratings are never deleted. No hard delete operations on listings or ratings tables. Second confirmed complaint results in permanent ban tied to phone number. Admin panel ban action writes to phone blocklist. Blocklist checked at OTP step. At least 5 photos and 1 video required before a listing can be submitted. Form validation on step 4. Terms must be accepted before first listing goes live. Publish button inactive until checkbox is checked. Acceptance timestamped in database. Advertiser ratings require minimum 20-character written text. Form validation on rating submission. Listing auto-deactivates when available beds reaches 0. Triggered on available_beds update.
